## 1. 진단 한 줄

> **아티팩트를 잘못 쓰고 있는 것이 아니다. 규칙이 파일이 아니라 발화로 전달되고 있다.**

그래서 규칙 한 줄을 고치는 데 손댈 곳이 셋이고, 레인을 띄울 때마다 그 규칙을
처음부터 다시 실어 보낸다. **컨텍스트 소모와 「기계화가 순탄치 않음」은 서로 다른
문제가 아니라 같은 하나의 증상이다.**

## 2. 왜 순탄치 않았나 — 원인 넷

넷은 나열이 아니라 사슬이다. 앞의 것이 뒤의 것을 만든다.

| # | 원인 | 근거 |
|---|---|---|
| 01 | **규칙이 아티팩트에 살아 세션이 자동으로 받지 못한다** — 함정 열여덟 · 권한의 선 · 보고 통로 · 깨울 자격 · 레인 문턱 40% 가 전부 규칙인데 아무 기계도 읽지 않는다 | 실측 — `find .claude -type f` 의 답은 `commands/align.md` **하나** |
| 02 | **그래서 관제탑이 매번 실어 나른다** — 레인에 규칙을 주는 유일한 길이 프롬프트다. 확인하려면 아티팩트를 다시 읽어야 한다 | 실측 — 허브 118.8 KB · 관제탑 76.2 KB |
| 03 | **레인은 맨바닥에서 시작한다** — `add_repo` → `clone` → `register_repo_root` 전에는 `CLAUDE.md` 조차 실리지 않는다. **그 세 단계는 저장소 파일로 못 없앤다**(아래 순환 의존). 저장소 훅이 맡을 수 있는 것은 **clone 뒤의 준비**다 | 실측 — 관제탑 함정 11 |
| 04 | **산문으로 실어 보낸 규칙은 낡는다** — 지시를 바꾸면 상시 프롬프트도 같은 턴에 고쳐야 하고, 안 고치면 레인은 낡은 쪽을 따른다 | 실측 — 관제탑 함정 10 |

**한 뿌리다.** 규칙이 **파일**이면 clone 에 딸려오고, 리뷰와 CI 와 룰셋이 보고, 고칠
곳이 한 곳이다. 규칙이 **발화**면 매번 실어 날라야 하고, 아무 기계도 보지 않고,
고칠 곳이 셋이다.

### 원인 03 에는 저장소가 못 넘는 선이 있다 — 순환 의존

**저장소 훅으로 저장소 자체를 부트스트랩할 수 없다**(리뷰 지적). `SessionStart` 훅의
도착지는 `.claude/settings.json` 이고, 그것은 **저장소가 이미 clone 되어 프로젝트
설정이 발견된 뒤에야** 읽힌다. 그러므로 `add_repo` → `clone` → `register_repo_root`
자체를 그 훅으로 없애려 하면 **훅을 읽으려고 그 절차를 먼저 끝내야 하는 고리**가 생긴다.

선은 이렇게 그어진다.

| 무엇 | 누가 | 왜 |
|---|---|---|
| `add_repo` → `clone` → `register_repo_root` | **계정·플랫폼 쪽** (D0 「아니오 · clone 전」) | 저장소 파일이 아직 읽히지 않는 구간이다 |
| 의존성 설치 · 데이터베이스 준비 · 검사가 도는 상태 | **저장소 `SessionStart`** (D3 예 → ①) | clone 뒤이므로 파일이 읽힌다. 문서의 예시도 정확히 이 몫이다 |

**그래서 원인 03 이 통째로 한 항목이 아니라 둘로 갈린다.** 앞의 셋은 이 설계가 없앨
수 있는 것이 아니고, 뒤의 준비만 저장소가 맡는다.

## 3. 이전 알고리즘 — 축 둘, 분기 여섯

「이것을 어디에 둘 것인가」에 답하는 절차다. **축이 둘이고, 둘은 직교한다**(리뷰 지적):
**D1~D5 가 「도착」**(그 항목이 사는 곳)을, **D0 이 「어디서」**(누가 적용하는가)를
정한다. 대장의 두 칸이 그 둘이다.

**「처음 나온 「예」가 도착지」로 읽지 않는다**(리뷰 지적). D2 의 「예」는 D5 로,
D3 의 「예」는 그 아래 셋으로 내려가는 **중간 결과**다. 도착지는 **화살표가 이름을
가리키는 자리**뿐이다.

```text
입력: 아티팩트가 지금 드는 것 하나

── 축 A. 어디서 — 누가 적용하는가 (도착지를 정하지 않는다)

D0  이 항목이 **필요로 하는 연산**을 지금 이 세션이 할 수 있는가?
    ※ 「API 가 있는가」가 아니다 — 룰셋도 Projects 도 API 는 있고, 이 세션이 403 일 뿐이다
    ※ **읽기와 쓰기를 함께 묻지 않는다**(리뷰 지적) — 조회 항목이면 읽기를, 변경 항목이면
      쓰기를 묻는다. 저장소 설정은 **읽히지만 `PATCH /repos` 가 403** 이라 「아니오」이고,
      보안 경보는 **바꿀 것이 없는데 읽기가 403** 이라 역시 「아니오」다
    예                          → **클라우드** — 이 세션이 PR 로 낸다
    아니오 · clone 전 구간이다  → **계정·플랫폼** (§2 순환 의존)
    아니오 · 그 밖의 전부       → **로컬** — 저자가 한다 (§5). 설정이든 조회든
    ※ **이 답은 도착지가 아니다**(리뷰 지적). 「로컬 세션」은 **실행자**이지 그 항목이
      사는 곳이 아니다 — 저장소 설정은 403 이든 아니든 **저장소 Settings 에 산다**.
      403 이 풀리면 이 칸만 바뀌고 **도착지는 그대로다**
    ↓ 어느 답이든 축 B 로 간다

── 축 B. 도착 — 그 항목이 사는 곳

    ※ **먼저 한 번 거른다**(리뷰 지적): 이것은 **두는 것인가, 하는 것인가?**
      조회 · 잡 재실행 · `clone` 처럼 **한 번 하고 끝나는 실행**에는 사는 곳이 없다.
      **되풀이될 것을 미리 정해 두는 규칙은 「두는 것」이다**(리뷰 지적) — `SessionStart`
      는 매 세션 도는 **규칙**이지 한 번의 준비가 아니고, 라운드를 세는 워크플로도
      **세는 규칙**이지 한 번의 셈이 아니다. 거르는 것은 **인스턴스**이지 규칙이 아니다.
      → **도착지 없음** — 축 B 를 타지 않고 대장에 그렇게 적는다. 축 A 의 답만 남는다
      ※ 이것이 없으면 「Projects 조회」가 D2 에서 GitHub 로 내려간 뒤 **D5 의 어느
        갈래에도 안 걸린다**
    ※ **그리고 축 B 의 도착지는 저장소 안 · GitHub 안 · 아티팩트 셋 중 하나다**
      (리뷰 지적 — 앞 판은 「저장소나 GitHub 안」이라 적어 **D1 의 아티팩트를 제 손으로
      잘라 냈다**). 셋 다의 **밖**에 있는 것만 축 B 를 타지 않는다 → **저장소 밖**.
      `~/.claude/settings.json` 의 `autoMode` 가 그 예다 — 저장소의 같은 이름 파일은
      읽히지 않는다(§5)

D1  지나간 일의 **기록**인가? (지켜야 할 규칙이 아니라)
    ※ 규칙도 지나도 참이다 — 가르는 것은 「따를 것인가, 참고할 것인가」다
    예 · 코드 옆에서 참조된다 → docs/adr/
    예 · 그림이나 경위다      → 아티팩트에 남는다
    아니오 ↓
D2  GitHub 이 그 자리를 이미 갖고 있는가?
    ※ 「부산물로 갱신되는가」만이 아니다 — 일감을 적는 **양식**도, CI 의 **실행 자체**도
      GitHub 이 이미 가진 자리다. 무엇으로 굳는지는 D5 가 가른다
    예    → GitHub (D5 로)
    아니오 ↓
D3  **훅이나 `permissions` 가 세션의 동작 자체를 바꿔야 하는가?**
    ※ 「기계가 본다」로 묻지 않는다(리뷰 지적) — 그러면 **CI 검사가 보는 것까지 전부
      여기서 끝나** 「조용히 깨지는 자리」 표가 `.claude/rules/` 에 닿지 못한다.
      이미 검사가 보고 있는 것의 **안내**는 강제가 아니다
    예 ↓ **무엇이 하는가 — 위에서부터 먼저 맞는 것 하나**(리뷰 지적). 대장이 이 셋을
         서로 다른 도착지로 보내므로 한 이름으로 끝내면 재현되지 않는다
      ① 세션을 **준비**시키는가?                → `SessionStart` 훅
      ② **훅이** 진행을 막거나 멈춰 세우는가?   → `PostToolUse` · `Stop` 훅
      ③ **도구 자체를 허용·금지**하는가?        → `permissions`
      ※ **② 에 「훅이」를 넣지 않으면 ③ 을 삼킨다**(리뷰 지적) — `permissions` 도
        「막는다」. 가르는 것은 **훅이 도중에 서는가, 설정이 애초에 막는가**다
      ※ **② 안에서 훅 종류를 고르는 것은 「언제 서야 하는가」다**(리뷰 지적).
        실행 자체를 **가로막아야** 하면 `PreToolUse` 이고, **하고 난 뒤에 보면 되는
        것**이면 `PostToolUse` 다. **#34 는 뒤쪽이다** — 그 이슈의 닫히는 조건이
        「파일을 고치는 순간 검사가 세션 안에서 돌고 **그 결과를 push 전에 본다**」이지
        push 를 막는 것이 아니다(실측 · 이슈 본문)
    아니오 ↓
D4  **Claude 세션의** 매 요청에 실려야 하는가?
    ※ D4 와 D4b 의 도착지는 **둘 다 Claude 세션만 읽는다** — 그래서 물음도 그 범위다.
      다른 도구가 읽을 것은 여기서 「아니오」로 빠져 D4c 에 닿는다
    예    → CLAUDE.md
    아니오 ↓
D4b **Claude 세션이** 특정 파일을 만질 때만인가?
    예    → .claude/rules/   (paths 글롭)
    아니오 ↓
D4c 읽는 것이 Claude 세션인가, 다른 도구인가?
    Claude 세션 → .claude/skills/  ← 기본 도착지
    다른 도구   → AGENTS.md

D5  (GitHub) 어느 자리인가? — **위에서부터 먼저 맞는 것 하나**(리뷰 지적)
    ※ 순서가 없으면 갈래가 겹친다 — 「조각 N」 제목 규약은 **사람이 적는 것이면서
      동시에 이슈끼리의 계층**이라 순서를 안 매기면 도착지가 둘이 된다
    1) 이슈끼리의 **계층**인가?                      → 서브이슈
    2) **이슈의 열림·닫힘으로 세어지는** 완료선인가?  → 마일스톤
    3) **이슈·PR 을 여는 자리의 모양**인가?           → 이슈 폼 · PR 템플릿
    4) 기계가 **세는 수치**인가?                      → Actions
    5) CI **실행의 제어**인가?                        → concurrency · 조건부 잡
    6) 저장소·브랜치의 **설정**인가?                  → 저장소 Settings · 룰셋

    ※ **2) 를 「진행률」로 넓게 읽으면 4) 와 겹친다**(리뷰 지적) — 리뷰 라운드 수도
      진행 상황이다. **마일스톤이 세는 것은 이슈의 열림·닫힘뿐**이므로 거기로 좁힌다
    ※ **3) 을 「이슈·PR 의」로 한정하지 않으면 6) 을 삼킨다**(리뷰 지적) — Actions 의
      secret 도 저장소 설정 필드도 **사람이 적는 필드**다
    ※ **다만 「사람이 적는 본문·필드」로만 적으면 이번엔 좁아서 샌다**(리뷰 지적) —
      이슈 폼은 `labels`·`type`·`projects` 를 **자동으로** 붙이는데 그건 사람이 적는
      것이 아니다. 그래서 「**여는 자리의 모양**」이다: 사람이 적는 칸과 폼이 자동으로
      붙이는 것이 **한 파일에 같이 산다**

    ※ **같은 값을 「보여 주는 창」은 도착지가 아니다**(리뷰 지적). 창은 원본이 여기
      어딘가에 놓인 **뒤의 이야기**이므로 알고리즘을 다시 타지 않는다 — 대장에 행이
      없는 것이 맞다. §11 의 「`mcp` 로 살아 있는 창」이 그것이다
```

**되돌림 둘이 이것을 나무가 아니라 고리로 만든다.**

1. **보드는 도착지가 아니라 창이다.** Projects 는 GraphQL 전용이고
   **이 클라우드 세션의 자격증명으로는 403 이다** — 가짜 토큰을 붙여도 문구가 바뀌지
   않았으므로 이 커넥터에 관한 한 자격증명 문제가 아니다(실측 2026-09-10).
   **다만 그것을 「기능이 영영 막혔다」로 읽지 않는다**(리뷰 지적) — Projects v2 와
   커스텀 필드는 공식 GraphQL API 로 조회되고, `project` 범위를 든 토큰이면 닿는다.
   실제로 **저자의 로컬 `gh` 는 200 이다**(관제탑 함정 16). **막힘은 규칙이 아니라
   측정이다.** 그러므로 규칙은 이렇게 좁힌다: **클라우드 세션이 읽어야 하는 값을
   보드에만 두지 않는다.** 보드 자체는 창으로 얼마든지 쓴다.
2. **아티팩트에 남긴 것도 규칙으로 굳으면 D1 로 되돌아온다.** 관제탑의 함정 열여덟이
   그 경로를 거쳤다 — 처음엔 「한 번 겪은 일」이었고, 열여덟이 되자 다음 세션이 반드시
   알아야 하는 것이 됐다. **기록과 규칙의 경계는 고정된 것이 아니라 같은 것이 두 번
   아프면 넘어간다.**

### 각 분기가 무엇으로 가르는가 — 그리고 무엇을 피하려 그렇게 물었는가

**분기의 물음은 전부 한 번씩 다시 쓰였다.** 아래는 그 결과이고, **왜 처음 물음이
틀렸는지는 여기 적지 않는다** — 그건 지나간 일이라 이 문서의 D1 이 아티팩트로 보낸다
([세 레인과 아홉 문턱 10판의 「이전 판정」 절](https://claude.ai/code/artifact/fe9d6b9c-ea26-4e9c-87ab-2de67942e796)).

| 분기 | 가르는 것 | 이렇게 묻지 않으면 |
|---|---|---|
| **D0** (축 A) | 이 항목이 **필요로 하는 연산**을 지금 이 세션이 할 수 있는가 — **「어디서」만 정한다** | 「API 가 있는가」로 물으면 룰셋도 Projects 도 「예」다. 「읽거나 바꿀 수 있는가」로 물으면 **읽기와 쓰기 권한이 다른 항목**이 샌다. 그리고 이것을 **도착지로 읽으면** 403 이 풀렸을 때 그 항목이 갈 곳이 사라진다 |
| **D1** | 따를 것인가(규칙), 참고할 것인가(기록) | 「지나도 참인가」로 물으면 **금지 규칙까지 삼켜** 훅·`rules` 로 갈 것이 아티팩트로 빠진다 |
| **D2** | GitHub 이 그 자리를 **이미 갖고 있는가** | 「부산물로 갱신되는가」로 물으면 **일감을 적는 양식**(이슈 폼·서브이슈)이 GitHub 에 닿지 못한다 |
| **D3** | **훅·`permissions` 가 세션의 동작 자체**를 바꿔야 하는가 | 「기계가 강제하는가」로 물으면 **CI 검사가 보는 것까지 삼켜** 「조용히 깨지는 자리」 표가 `rules/` 에 닿지 못한다 |
| **D4·D4b** | **Claude 세션이** 늘 / 그 파일을 만질 때 필요로 하는가 | 소비 주체를 안 물으면 **다른 도구용 안내가 `CLAUDE.md` 로 끝나** `AGENTS.md` 가 닿지 못한다 |
| **D4c** | 읽는 것이 Claude 세션인가, 다른 도구인가 | 없으면 `skills` 와 `AGENTS.md` 가 **같은 답에서 두 도착지**가 된다 |
| **D5** | 위에서부터 먼저 맞는 것 하나 — 계층이 먼저 | 순서가 없으면 「조각 N」 규약처럼 **사람이 적으면서 동시에 계층**인 것의 도착지가 둘이 된다 |

**D1 의 「예」가 둘로 갈리는 기준은 「코드 옆에서 참조되는가」다** — ADR 도 기록이지만
저장소로 간다. 리뷰 답글은 머지되면 저장소에서 찾을 수 없다.

**D4b 가 셋째 답인 이유** — `.claude/rules/` 는 `paths` 글롭에 맞는 파일을 읽거나
고칠 때만 실린다(실측 · Context7). 「늘 필요하다」와 「부를 때만 필요하다」 사이가
비어 있었고, 이 저장소의 「조용히 깨지는 자리」 표가 정확히 그 모양이다.

### 알고리즘이 고른 것 중 문서에서 확인한 형태 (전부 실측 · Context7)

- **`concurrency` 는 `group` 과 `cancel-in-progress` 가 짝이다.** 표준형은
  `group: ${{ github.workflow }}-${{ github.ref }}` + `cancel-in-progress: true` 다.
  워크플로 이름을 넣어야 다른 워크플로의 잡을 죽이지 않고, **`cancel-in-progress` 가
  없으면 낡은 실행이 죽지 않는다** — 그룹만 걸면 「돌고 있는 것 하나 + 기다리는 것
  하나」가 허용되어, 낡은 검증은 끝까지 돌고 새 검증은 그만큼 기다린다(리뷰 지적).
  **그리고 `cancel-in-progress` 를 무조건 켜면 `main` 도 취소된다**(리뷰 지적) —
  같은 워크플로가 PR 과 `main` push 양쪽에서 돌기 때문이다. #54 가 「`main` 은
  취소하지 않는다」고 적었으므로 조건식까지가 설계다:
  `cancel-in-progress: ${{ github.event_name == 'pull_request' }}`.
  **머지된 것이 초록인지는 끝까지 봐야 한다.**
- **`Stop` 훅에 `prompt` 형이 있고 응답이 `{ok, reason, impossible}` 이다.**
  `$ARGUMENTS` 로 훅 입력이 프롬프트에 치환된다 — #35 가 찾던 모양이 이미 문서에 있었다.
- **`SessionStart` 는 `matcher: "startup|resume"`** 로 건다.
- **이슈 폼은 `labels`·`type`·`projects` 를 자동으로 붙인다** — 라벨 붙이는 손일도
  같이 사라진다.
- **서브에이전트는 `skills:` 로 스킬을 프리로드한다.** #46 이 「스킬이 먼저 있어야
  한다」고 보류한 이유가 기술로 강제되는 자리다.

### #55 가 왜 「클라우드」 칸에 서는가

> 워크플로가 path 필터로 건너뛰면 *“checks … remain in a Pending state … pull requests
> will be blocked from merging.”*
> 그런데 잡이 `if:` 로 건너뛰면 *“reports its status as **Success** and will not prevent
> a pull request from merging, **even if the job was configured as a required check**.”*

**`paths-ignore` 는 저장소를 잠그고, 건너뛴 잡은 잠그지 않는다**(실측 · Context7).
그러므로 이 항목은 **워크플로 파일 하나로 표현되고**, 대장의 「어디서」는 **클라우드**다.

**여기까지가 이 설계의 몫이다.** 어느 구현을 고를지와 그 기법은 **#55 가 정한다** —
[#55 에 옮겨 적었다](https://github.com/pdw96/ai-production-risk-early-warning/issues/55).
다만 대장이 서 있으려면 그중 **하나만은 여기 남아야 한다**: 구현 중 하나
(느린 검사를 별도 잡으로 떼고 **그 잡을 필수 문맥으로 하나 더 거는** 길)는
**룰셋 쓰기가 필요해 로컬이 한 번 붙는다.** 그래서 대장의 그 칸은 「클라우드」이되
**조건이 하나 달린다.** 나머지 길은 클라우드로 끝난다.

**그리고 `validate` 라는 이름은 어느 길에서도 남는다** — 그것이 룰셋이 기다리는
문맥이기 때문이다. §5 의 룰셋 줄이 **#55 의 짝이 아닌** 이유가 이것이다.

**다만 25분이라는 전제 자체를 다시 재야 한다.** 2026-09-10 09:26–09:31 UTC 의
`validate` 는 **4분 56초**였다(PR #56 · 문서 한 장). #55 본문이 근거로 든 #47 의 실제
소요를 재 보기 전에는 이 항목의 회수를 25분으로 적지 않는다. **`timeout-minutes: 25`
를 소요로 읽는 것은 이 프로젝트가 이미 한 번 밟은 함정이다.** <sub>미검증 — #47 의
실제 소요는 재지 않았다</sub>

## 5. 로컬 명령지 — 이 세션이 손도 못 대는 것

전부 이 세션에서 직접 재서 확인한 막힘이다. 가르는 법 하나 — **HTTP 코드가 있으면
프록시나 권한, 없으면 분류기.**

| 할 것 | 왜 클라우드가 못 하나 | 저자가 하는 일 |
|---|---|---|
| 저장소 설정 둘 | `PATCH /repos` **403** | Wiki 끄기 · Update branch 켜기. **auto-merge 는 켜지 않는다.** 정확히는 **켜는 것만으로 머지되지 않는다** — PR 마다 따로 활성화해야 한다(리뷰 지적). 그런데 **켜는 순간 에이전트의 `enable_pr_auto_merge` 가 실제로 동작하게 되고**, 그것이 활성화되면 CI 초록에 즉시 머지된다. 머지된 11건 중 8건에서 👍 가 CI 초록보다 늦었으므로, 그 여덟은 판정 전에 들어갔을 것이다. **끄는 것은 「자동 머지를 막는다」가 아니라 「그 문을 열지 않는다」다** |
| 룰셋의 필수 검사 문맥 | 룰셋 쓰기 **403** · `bypass_actors` 도 비어 있다 | **필수 잡의 이름이 실제로 바뀌는 변경을 고른 경우에만** 그 변경과 **같은 시각에** 문맥 이름을 바꾼다. 먼저 바꿔도 나중에 바꿔도 모든 PR 이 막히므로 **짝이어야 한다**. **#55 는 이름을 바꾸지 않는다**(리뷰 지적) — 어느 구현이든 `validate` 를 남긴다(§4). **다만 뗀 잡을 필수 문맥으로 하나 더 거는 구현을 고르면 여기서 클릭 한 번이 필요하다** — 이름 **변경**이 아니라 **추가**다. 그 밖의 구현이면 그것도 없다. 이 줄은 **지금 할 일이 아니라 조건**이다 |
| Projects 보드 | **이 세션의 자격증명으로** GraphQL **403** — 가짜 토큰으로도 문구가 안 바뀌므로 이 커넥터에 관한 한 자격증명 문제가 아니다. **다만 `project` 범위를 든 로컬 `gh` 는 200 이다** | **커스텀 필드를 금지하지 않는다**(리뷰 지적). 규칙은 §3 의 좁힌 형태 하나다 — **클라우드 세션이 읽어야 하는 값을 보드에만 두지 않는다.** 로컬에서만 쓰는 필드는 얼마든지 만든다 |
| 보안 경보 셋 | code scanning · secret scanning · Dependabot 경보 **전부 403** | 브라우저에서 본다. **다만 `dependabot.yml` 같은 설정 파일은 PR 로 들어간다** — 경보를 읽는 것과 설정을 두는 것은 다르다. 그리고 `security-review` 스킬이 이 공백을 부분적으로 메운다(§6) |
| claude.ai 계정 설정 | 계정 수준이라 세션 안에 통로가 없다 | **GitHub MCP 커넥터가 두 벌이다**(실측) — 하나를 끈다. Calendar · Drive · Nimble · Draw.io 는 이 저장소 일과 무관하므로 이 프로젝트에서는 끈다. **Context7 은 남긴다** — 이 설계의 실측 다섯이 거기서 나왔다 |
| 분류기 설정 | **저장소 `.claude/settings.json` 은 읽히지 않는다** — 검증되지 않은 허용 규칙 주입을 막기 위해서다 | `~/.claude/settings.json` 의 `autoMode` 에서만 된다. **배열에서 `"$defaults"` 를 빼면 내장 보호가 통째로 사라진다** |
| Actions 조작 | `workflow_dispatch` · 재실행 · secrets · variables **전부 403** | 빨간 잡을 다시 돌려야 하면 저자가 누른다. **「막혀 있으니 안전하다」에 기대지 않는다** — 같은 머지 호출이 하루는 막히고 하루는 통과했다 |

## 6. 이미 손에 있는데 안 쓰는 것

**플러그인 0개 · 커넥터 여덟(여섯 활성) · 스킬 스물여섯**(실측). 새로 들일 것이
아니라 **이미 붙어 있는데 자리를 안 준 것**을 센다.

| 스킬 | 어느 갈래 | 무엇을 대신하나 |
|---|---|---|
| `artifact-capabilities` | 아티팩트 | **아티팩트는 정적 페이지가 아닐 수 있다.** `mcp` 능력을 선언하면 페이지가 열릴 때마다 뷰어의 커넥터를 호출한다 → §7 |
| `session-start-hook` | D3 예 → ① | **빈 자리 하나를 그대로 덮는다.** 웹 세션이 검사를 돌릴 수 있게 저장소를 준비하는 것이 이 스킬의 정의된 목적이다 |
| `update-config` | D3 예 → ②·③ | `.claude/settings.json` 의 훅·permissions — #34·#35 가 손으로 쓰려던 것 |
| `skill-creator` | D4c 세션 | **#33 의 스킬을 만드는 도구.** 게다가 평가를 돌려 **스킬이 실제로 걸리는지 잰다** — 「설명만 그럴듯하고 안 불리는 스킬」을 막는다 |
| `code-review` · `simplify` | G5 | **#29 가 헤드리스로 굳히려는 그것이다.** `--comment` 로 PR 인라인, `--fix` 로 작업 트리 적용. `simplify` 는 품질 전용이라 결함 사냥과 정리를 갈라 준다 |
| `security-review` | G5 | **경보 조회를 대신하지 못한다**(리뷰 지적). code scanning · secret scanning · Dependabot **경보 조회는 403 이라 「어디서」가 로컬이다**(D0 · §5) — 저자가 브라우저에서 본다. 이 스킬이 하는 것은 **브랜치의 변경을 직접 훑는 별도의 검토**이고, 그것이 클라우드에서 되는 것뿐이다. **둘을 바꿔 치면 실제 경보를 안 보게 된다** |
| `dataviz` | Actions | 라운드 계기판은 **차트**다. Actions 가 수치를 세면 그리는 쪽의 규칙이 필요하다 |

## 7. 아티팩트 능력 — 쓸 것 하나, 기각할 것 둘

쓸 수 있는 것은 `artifact` · `assets` · `db` · `downloads` · `mcp` · `room` ·
`sample` · `self` 여덟이다.

**`mcp` 하나가 쓸 만하다.** 「지금 도는 파이프라인」과 「라운드 계기판」이 손으로 베낀
스냅숏 대신 **이슈와 PR 을 직접 읽는 창**이 된다. 그러면 이 저장소가 「상수」라 부른
**함정 07(머지 하나가 문서 넷을 낡게 만든다)이 그 문서에 한해 사라진다** — 손으로
갱신할 문서를 줄이는 것이 아니라 **갱신 자체를 없앤다.**

<sub>**미검증** — 능력 목록이 *“None are connected right now”* 라고 답했고, 아티팩트
런타임에서 GitHub 커넥터를 실제로 호출해 본 적이 없다. 그리고 공식 문서가 둘을
못박는다: 커넥터를 쓰는 페이지는 **공개 링크로 공유할 수 없고**, 호출은 **보는 사람의
계정**으로 나간다. 저자 혼자 보는 지도라면 둘 다 문제가 아니다.</sub>

**`db` 와 `artifact` 는 기각한다.** 둘이면 허브의 `#state` 를 「제대로」 만들 수 있다
— 뷰어가 눌러 저장하는 진짜 체크리스트가 된다. **그래서 기각한다.** 이 설계 전체가
「상태는 GitHub 이슈 한 곳에 산다」 위에 서 있고, 저것을 켜는 순간 **상태가 사는 곳이
다시 둘이 된다.** 되고 안 되고의 문제가 아니라 **이미 내린 결정을 뒤집는가**의 문제다.

## 8. 검토했으나 넣지 않은 것

기각한 이유를 적어 두지 않으면 다음 세션이 다시 제안한다.

| 기각 | 이유 |
|---|---|
| **CODEOWNERS** | **둘을 갈라야 한다**(리뷰 지적). **리뷰 자동 요청은 룰셋 없이도 된다** — 파일만 두면 일치하는 파일의 소유자에게 리뷰가 걸린다. 룰셋을 켜야 생기는 것은 **머지 차단**이고, 그것은 저자 혼자인 저장소에서 자기 PR 을 자기가 승인할 수 없어 모든 PR 을 멈춘다. **지금 안 넣는 이유는 라우팅할 협업자가 없어서**이고, 협업자가 생기면 **차단 없이 라우팅만** 쓰는 선택지가 남아 있다 |

## 10. 순서 — 무엇이 무엇 위에 서는가

크기가 아니라 **뒤엣것이 그 위에 서는가**로 정한다.
**착수 결정은 저자의 것이다**(#48) — 이 문서는 순서만 적는다.

1. **#33 을 「관제탑 규칙을 스킬로 내린다」로 구체화한다.**
   지금 #33 의 근거란은 「아직 어느 문서에도 적혀 있지 않다. 집기 전에 먼저 적을 것.」
   이고 **이 문서가 그 자리를 메운다.** 그 위에 서는 것은 **서브에이전트뿐이다**(#46
   — `skills:` 로 프리로드하므로 스킬이 먼저 있어야 한다).
2. **`SessionStart` 훅으로 clone 뒤의 준비를 자동으로 한다.**
   **#33 과 독립이다**(리뷰 지적). 이 훅이 맡는 것은 의존성 설치·데이터베이스 준비·
   검사가 도는 상태이고, 그 재료는 **이미 저장소에 있다** — `backend/requirements.txt`,
   `frontend/package-lock.json`, 마이그레이션, 검사. **스킬이 없어도 값이 난다.**
   1·2 는 아무 순서로나 집어도 되고, 둘을 나란히 해도 된다.
   **이슈가 없으므로 여는 것이 이 단계의 절반이다.**
3. **#52 이슈 폼 · #54 concurrency.** 둘 다 앞의 것에 기대지 않고 값이 즉시 난다.
4. **#53 서브이슈 · #55 CI 분리.** #53 은 **저자의 클릭과 짝을 이룬다.**
   **#55 는 아니다**(리뷰 지적 · 정정) — 필수 문맥을 **추가하는** 구현을 고르지
   않는 한 **워크플로 PR 하나로 끝난다**(§4). 있지도 않은 로컬 단계를 기다리지 않는다.
5. **#34 · #35 훅 · #36 ADR.** 허브가 이 셋의 회수를 **사실상 0** 으로 판정해 두었다.

## 이 문서가 리뷰를 거친 자리

**리뷰 쉰네 건을 반영했다** — 코덱스 열 라운드에서 마흔아홉

**다만 그 경위가 남긴 판단 하나는 규칙이라 여기 남는다.** 열 라운드 중 **아홉에서
같은 종류가 나왔다** — 「알고리즘이 대장의 어느 행을 재현하지 못한다」, 또는 「한쪽을
고치고 그 짝을 안 고쳤다」. **줄어들기는 했으나 끊기지 않았다.** 이 저장소는 그런 짝을 기계에 맡기지만(`test_claude_md.py` ·
`test_ci_workflow.py`), **이 문서 안의 짝은 아무도 보지 않는다.** 그래서 §11 의 빈
자리에 후보가 하나 더 있다: **알고리즘이 대장의 행을 한 줄씩 재현하는지 세는 검사.**
이 PR 은 그것을 만들지 않는다.

**열한 번째 라운드가 지적 없이 돌아왔다**(2026-09-10 · `3b67a8e` · *"Didn't find any
major issues"*). **그것이 이 문서가 옳다는 뜻은 아니다** — 열 라운드 내내 새 지적은
**앞 라운드의 고침이 판 자리**에서 나왔고, 열한 번째는 **넓힌 셋이 다시 삼키지
않는지**만 물었다. 여기서 멈추는 이유는 다 맞아서가 아니라, **이 두 문서 안에서 닫히는
것이 더 없기 때문**이다. 남은 물음은 전부 **이 설계를 실제로 집어 본 뒤에야** 답이
나온다.
