## 구조 (현재)

```
경보    운영 현황(/) · 리스크 보드(/risks)
ERP     기준정보관리(/master)
        구매관리(/purchases)
        재고관리
          └ 재고현황(/materials)            자재별 로트 + 14일 수급 판정
          └ 창고별 재고
              └ 원재료창고(/materials/warehouses/raw)
              └ 생산창고(/materials/warehouses/production)
              └ 제품창고(/materials/warehouses/products)
        생산관리(/orders)
        품질관리(/quality)                  IQC·PQC·OQC 기록
        영업관리(/sales)                    출하 관점 요약만
```

창고 규칙(DB 제약으로 강제):

- 원재료창고 — 자재만
- 생산창고 — 원재료창고에서 이동한 자재 + **검사 대기·불합격** 완제품
- 제품창고 — **출하검사 합격 완제품만** (`제품창고 ⟺ 합격` 양방향 CHECK)

## 열려 있는 것 / 다음 세션이 정해야 할 것

### 재설계가 건드릴 가능성이 큰 지점 (추정)

- **완제품의 창고 이동이 행위로 남지 않는다.** `제품창고 ⟺ 합격` 을 양방향으로 막은
  결과, 합격 판정이 곧 이동이다. 후속 재고이동의 대상은 자재의
  `원재료창고 → 생산창고` 하나만 남는다. 완제품 이동도 이력으로 남기려면 이 제약을
  다시 한쪽 방향으로 풀고 `이관 대기` 를 되살려야 한다 — 이번 세션에 한 번 넣었다
  뺀 것이라 되돌리는 비용 자체는 작다.
- **서브메뉴가 재고관리에만 있다.** 다른 모듈에 화면이 쌓이면 같은 기준을 적용할지
  결정해야 한다(원래 제안 기준: 한 모듈에 독립 화면 3개 이상).
- **영업관리가 얇다.** 출하 일정·수주 엔티티가 없어 요약 표 하나뿐이다.

### 손대지 않은 남은 계획 (README 「향후 확장 계획」)

1. 출하 리스크 (세 번째 리스크 타입) — `risk_type` 은 아직 `납기`/`자재` 둘뿐이다
2. 재고이동 처리 (이 저장소 최초의 본격 쓰기 워크플로)
3. 검사 결과를 자재·생산 판정에 반영 (지금은 OQC만 수량 흐름에 관여)
4. 설비
5. AI 브리핑
