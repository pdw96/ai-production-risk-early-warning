# 정렬 게이트 통과 기록 — 허브의 `#state` 를 걷어낸다 (2026-09-11)

이 문서는 **작업 결과가 아니라 작업 전의 합의**다. `/align` 게이트를 통과한 시점의
이해와 근거를 남겨, 나중에 **무엇이 확인된 사실이고 무엇이 가정 위에 서 있었는지**가
보이도록 한다. 편집 대상은 저장소가 아니라 **아티팩트**이므로, 이 문서가 그 편집에
대해 저장소에 남는 유일한 기록이다.

- 확인 시점: **2026-09-11** (별도 표기가 없는 실측은 전부 이 날짜)
- 확인 수단: `git fetch` 후 `git log` · `mcp__github__issue_read`(#57) ·
  `mcp__github__list_issues` · `curl` GitHub REST(`milestones` · `issues?milestone=1`) ·
  `Artifact read`(허브 전문 1078줄을 내려받아 행 번호로 지목)
- 기준 커밋: `main@3fcdaf1` — **저장소 쪽 실측이 선 자리**. 아티팩트 쪽 실측은
  커밋과 무관하고 **날짜(2026-09-11)뿐**이다. 아티팩트는 저장소 밖에 있고 이 세션
  밖에서도 바뀐다
- 기준 아티팩트 판: `Artifact read` 로 받은 **118.8 KB · 1078줄** 판
- 라벨 규약: **실측** = 명령·API·파일로 직접 확인 / **추정** = 내 판단 / **미검증** = 확인해야 하는데 못 함

## 1. 무엇을 하기로 했나

허브 아티팩트 [파이프라인 조기경보](https://claude.ai/code/artifact/bbb2fc87-6daf-4075-a27e-3f2d5d0798a1)
가 **항목 상태를 자기 안에 들고 있다.** 그것을 걷어내고, 진행 상태를 묻는 사람은
**GitHub 마일스톤과 이슈**를 보게 한다. 이슈
[#57](https://github.com/pdw96/ai-production-risk-early-warning/issues/57) 이 그 일감이다.

**상태가 두 곳에 살면 한쪽이 반드시 낡고, 이미 낡았다.** (실측)

```html
<script id="state" type="application/json">{"v": 1, "items": {"claude-md": "done",
  "unit-default": "done", "ci-postgres": "done", "golden-cases": "done"}}</script>
```

완료선은 다섯인데 `engine-pinned-tests` 가 빠져 있다. 같은 것을 GitHub 에 물으면:

```
$ curl -s ".../milestones?state=all"
1  P0 — 완료선   open 0  closed 5
$ curl -s ".../issues?milestone=1&state=all"
42 closed CLAUDE.md 를 쓴다 (claude-md)          41 closed 단위 기본값을 없앤다 (unit-default)
40 closed 검사 엔진을 공용 픽스처로 모은다        39 closed 손으로 검산한 골든 케이스
38 closed CI 를 실제 엔진에 올린다 (ci-postgres)
```

**아티팩트 쪽이 틀렸다.** 다섯이 다 닫혔는데 허브는 넷만 안다.

## 2. 무엇이 끝인가 — 관측 가능한 형태로

발행한 뒤 같은 아티팩트를 다시 읽어 아래를 **전부** 확인한다.

| # | 확인할 것 | 어떻게 본다 |
| --- | --- | --- |
| 1 | `id="state"` 가 없다 | `grep -c 'id="state"'` → `0` |
| 2 | 손으로 적은 상태값을 읽는 코드가 없다 | `grep -n 'statusOf\|state\.items\|STATUSES\|renderSeg\|schedulePublish\|fullDoc'` → 없음 |
| 3 | `artifact` 능력이 꺼져 있다 | `grep -n "window\.claude"` → 없음. 발행 시 `capabilities: {}` 로 비운다 |
| 4 | 진행률을 **마일스톤 링크**가 답한다 | 완료선 절과 항목 열셋에서 해당 이슈·마일스톤으로 링크가 나간다 |
| 5 | BUDGET 절에 「25.9k」가 없다 | `grep -c '25\.9k'` → `0` |
| 6 | **진단과 근거는 그대로 있다** | 항목 열셋의 `lead`·`ev`·`rx`·`excl`·`win` 문구가 편집 전후 동일 |

6번이 반대 방향의 안전장치다 — #57 이 *"항목의 진단과 근거는 지우지 않는다 — 그것은
과거 실측이라 지나도 참이고, 허브가 존재하는 이유다"* 라고 못박았다. **걷어내는 것은
「지금 어디까지 왔는가」뿐이다.**

## 3. 범위 — 포함과 명시적 제외

**포함** (전부 사용자 확인)

1. `<script id="state">` 와 그것을 읽고 쓰는 코드 전량
2. 항목마다 붙은 상태 버튼(신규 / 확인 중 / 조치 완료)과 진행률 바 — **통째로**
3. `artifact` 능력 선언 — **끈다**
4. 완료선 다섯 줄의 상태 배지 → 해당 이슈(#38–#42) 링크로
5. BUDGET 절의 「`notion-query-data-sources` 하나가 25.9k」

**명시적 제외**

| 제외 | 왜 |
| --- | --- |
| 항목 열셋의 진단·근거·처방 문구 | #57 이 남기라고 적었다. 과거 실측이라 지나도 참이다 |
| `CLAUDE.md` 의 아티팩트 목록 교정 | [#58](https://github.com/pdw96/ai-production-risk-early-warning/issues/58) 이 따로 있다 |
| 다른 여덟 아티팩트 | 설계도 §9 가 각각 다른 처분을 권고한다. 이 일감은 허브 하나다 |
| 저장소 코드 | 이것은 **아티팩트 편집**이다. 저장소에 남는 것은 이 문서뿐이다 |

## 4. 제약과 함정 — 재현 증거와 함께 (실측)

| 3 | **아티팩트는 이 세션 밖에서도 바뀐다.** 남의 판 위에 얹지 않은 발행은 거절된다 | 관제탑 함정 12. **발행 직전에 다시 읽는다** |

## 5. 접근 방식과 기각한 대안

**택한 것** — 걷어낼 자리를 행 번호로 먼저 지목하고(아래), 상태가 답하던 자리마다
**그 답을 가진 GitHub 자원의 링크**를 넣는다. 항목 열셋의 `id` 가 이슈와 **1:1 로
맞는다**(실측):

```
ci-postgres 38 · golden-cases 39 · engine-pinned-tests 40 · unit-default 41 · claude-md 42
biting-tests 27 · linters 28 · code-review 29 · readme-test 30 · docs-layout 31
hooks 34 · stop-gate 35 · adr 36
```

그래서 **상태 버튼 자리에 그 이슈 링크 하나**가 들어가면, 세는 일도 보는 일도 전부
GitHub 이 한다. 진행률 바 자리에는 [P0 마일스톤](https://github.com/pdw96/ai-production-risk-early-warning/milestone/1)
링크가 선다.

걷어낼 자리 (기준 판의 행 번호, 실측)

| 행 | 무엇 |
| --- | --- |
| 250 | `<script id="state">` |
| 174–186 | `.seg` 스타일 |
| 503–507 | `STATUSES` |
| 510–516 | `stateEl` · `state` · `readOnly`/`ns`/`timer` · `statusOf` |
| 590 · 599 · 606 | 완료선이 상태로 「남은 것 N」을 세고 배지를 그리는 자리 |
| 619–631 | `renderProgress` — 진행률 바와 「이 페이지에 저장됩니다」 |

**기각한 대안**

| 기각 | 이유 |
| --- | --- |
| 값만 고친다 (`engine-pinned-tests: "done"` 을 더한다) | 두 곳에 사는 **구조가 그대로**라 다음 머지에 또 낡는다. 지금 낡은 것이 그 증명이다 |
| `db` 능력으로 진짜 저장소를 붙인다 | 설계도 §7 이 이미 기각했다 — 상태가 사는 곳이 둘이 된다 |
| 버튼은 두고 저장만 끊는다 | 눌러도 안 남는 장식이 된다. 사용자 발화로 기각됐다 |
| 완료선 다섯 줄에 상태 배지를 남긴다 | 배지 값을 마일스톤에서 읽을 수 없으므로 **손으로 적은 값이 다시 들어온다**. 사용자 발화로 기각됐다 |

## 6. 남은 가정 — 무엇이 검증되지 않았나

- **미검증** — 발행 시점에 허브가 이 문서의 기준 판 그대로인지. 다른 세션이 건드렸으면
  발행이 거절된다. **발행 직전에 다시 읽어 해소한다**(함정 3).
- **미검증** — `capabilities: {}` 로 능력을 비운 뒤 기존 뷰에서 버튼이 어떻게 보이는지.
  버튼 자체를 지우므로 문제가 되지 않을 것으로 본다(**추정**).
- **추정** — 항목 `id` ↔ 이슈 번호 대응은 제목의 괄호 슬러그로 맞췄다. 열셋 전부
  일치하지만 **이슈 본문까지 대조하지는 않았다.**
- **실측이 아닌 자리** — 이 편집이 참인지 볼 기계가 없다(함정 5). §2 의 여섯 줄이
  사람이 밟는 대조표이고, 그것을 밟은 결과를 이 문서에 덧붙인다.

**무엇이 점수를 올렸나.** 질문 셋 중 첫째 하나가 1·2·3 을 동시에 올렸다 —
「스테이지」라는 한 단어의 지시 대상이 세 항목을 다 누르고 있었다. **저장소를 아무리
읽어도 안 나오는 종류**였고, 루브릭이 항목 1·2·3 을 실측으로 못 올리게 막아 둔
이유가 그것이다.

**무엇이 가정 위에 서 있나.** 항목 4·5·6 은 실측 상한 2점이다. 셋 다 **이 세션에서
확인한 아티팩트 한 판** 위에 서 있고, 그 판이 바뀌면 행 번호부터 어긋난다 —
그래서 발행 직전 재독이 절차에 들어가 있다.
