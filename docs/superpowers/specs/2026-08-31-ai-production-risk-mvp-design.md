# AI 생산 리스크 조기경보·일일 운영 브리핑 설계

## 목적과 범위

가상의 소재 제조공장 합성 데이터를 바탕으로, 생산관리자가 매일 아침 납기 위험·향후 14일 자재 부족·부서별 권장 조치를 한 화면에서 판단하는 로컬 실행 MVP를 만든다. 실제 회사, 제품, 거래처, 수치 및 실제 LLM 연동은 사용하지 않는다.

범위는 생산계획, 일별 실적, BOM, 재고, 예정 입고, 리스크 상태 관리까지다. LOT/FIFO, 품질·설비 데이터, 인증, Docker, 외부 API, 실제 AI 모델은 제외한다.

## 아키텍처

`frontend`는 Next.js App Router·TypeScript·Tailwind CSS·Recharts로 구성한다. 모든 화면은 `NEXT_PUBLIC_API_BASE_URL`의 FastAPI API를 호출하며, 데이터 JSON을 직접 하드코딩하지 않는다.

`backend`는 FastAPI·SQLAlchemy·SQLite·Pandas로 구성한다. API 계층은 조회와 상태 변경만 담당하고, `services` 계층이 납기 및 자재 수급 계산을 수행한다. Pydantic 스키마가 성공 응답을 `{ "data": ... }`, 오류 응답을 `{ "detail": "..." }` 형태로 일관되게 직렬화한다.

```text
Next.js pages/components
        │ HTTP
FastAPI routers → services (risk calculations) → SQLAlchemy → SQLite
        ▲                                              │
        └────────────── seed.py (fixed seed) ──────────┘
```

## 데이터 모델

| 테이블 | 주요 데이터 | 역할 |
| --- | --- | --- |
| `products` | 코드, 제품명 | 가상 제품 5개 기준정보 |
| `orders` | 오더번호, 제품, 납기, 계획수량 | 오더 30개와 일일 계획의 기준 |
| `daily_production` | 날짜, 오더, 계획수량, 실적수량 | 과거 30일 이상 실적 및 향후 14일 계획 |
| `materials` | 코드, 명칭, 현재/안전 재고 | 원자재 15개 기준정보 |
| `bom_requirements` | 제품, 자재, 단위 소요량 | 계획을 자재 수요로 변환 |
| `purchase_receipts` | 자재, 예정일, 예정수량 | 예정 입고 반영 |
| `risk_statuses` | 결정적 리스크 키, 상태 | 신규/확인 중/조치 완료 상태의 영속 저장 |

초기화 스크립트는 실행 당일을 운영 기준일로 사용한다. 난수 시드는 고정하고 기준일을 난수 생성 입력에 포함해, 같은 날짜에는 동일한 합성 데이터가 재현되며 다른 실행일에는 날짜 축이 자연스럽게 이동한다. 생성 데이터에는 정상·주의·위험 상태가 모두 존재하도록 검증 로직을 둔다.

## 계산 규칙

### 납기 위험

1. 누적 실적은 기준일 이전(포함) `daily_production.actual_quantity`의 합계다.
2. 최근 일평균 생산량은 기준일을 포함한 과거 7일 실적의 일평균이다. 0이면 안전하게 완료예정일을 산출하지 않고 위험으로 본다.
3. 잔여수량을 일평균 생산량으로 나눠 올림한 일수를 기준일에 더해 예상 완료일을 산출한다.
4. 예상 완료일이 납기일보다 늦으면 `위험`, 납기일까지 남은 일수가 1일 이하면 `주의`, 그 외 `정상`이다.
5. 위험 근거에는 완료예정일·납기일·잔여수량을 포함한다.

### 자재·안전재고 부족

1. 기준일의 현재 재고에서 기준일 포함 14일간 오더별 계획수량 × BOM 단위 소요량을 일자별로 차감한다.
2. 각 일자 예정 입고량을 그 날짜에 먼저 더한 뒤 계획 소요량을 차감한다.
3. 재고 소진 예상일은 재고가 0 이하가 되는 첫 날짜이며, 14일 내 안전재고 미만 또는 0 이하가 되는 자재는 부족 예상으로 표시한다.
4. 부족 예상이면 예정 입고 유무·소진 시점에 따라 구매 입고일 재확인 또는 생산 우선순위 조정 권고를 선택한다. 안전재고 미만이지만 소진하지 않으면 안전재고 상향 검토, 그 외 정상 모니터링 유지다.

## API 계약

| 메서드·경로 | 응답 `data` |
| --- | --- |
| `GET /api/dashboard` | KPI, 7일 추이, 상위 5건 납기/자재 위험, 권장 조치 |
| `GET /api/orders` | 오더별 계산 결과 목록 |
| `GET /api/orders/{order_id}` | 단일 오더의 계산 결과와 최근 실적 |
| `GET /api/materials` | 자재별 14일 수급 계산 결과 |
| `GET /api/risks` | 납기·자재 리스크 통합 목록과 영속 상태 |
| `PATCH /api/risks/{risk_id}/status` | 유효 상태 저장 후 갱신된 리스크 |

없는 오더·리스크는 404, 유효하지 않은 상태는 422를 반환한다. 목록이 비어도 성공 응답의 배열을 반환한다.

## 화면 설계

- `/`: KPI 4개, 7일 계획/실적 차트, 위험 오더·자재 상위 5개, 오늘 권장 조치. 카드와 행은 관련 상세 화면으로 이동한다.
- `/orders`: 오더 테이블과 선택 오더 상세 패널. 상태는 아이콘과 텍스트 배지로 함께 보여준다.
- `/materials`: 자재 수급·안전재고 테이블과 재고 소진일 및 권장 조치.
- `/risks`: 납기·자재 통합 보드. 상태 선택 컨트롤로 변경하고 즉시 API 재조회한다.

밀도 높은 데스크톱 통제실 방향의 어두운 중성 기반 UI를 사용한다. 숫자는 `ko-KR` 형식, 날짜는 `YYYY.MM.DD`, 퍼센트는 한 자리 소수점으로 표기한다. 각 페이지는 로딩·빈 상태·API 오류 상태를 포함한다.

## 테스트와 검증

pytest로 납기 규칙(위험/주의/정상/생산량 0)과 자재 시뮬레이션(계획 소요, 입고 반영, 안전재고 미만, 소진)을 테스트한다. API 테스트는 초기화된 임시 SQLite DB에서 목록·상세·상태 영속 갱신을 검증한다.

로컬 검증은 백엔드 `uvicorn`과 프론트엔드 `next dev`를 별도 프로세스로 실행하고, HTTP 응답 및 브라우저 빌드를 확인한다.
