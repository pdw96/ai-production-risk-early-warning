## 1. 무엇을 하기로 했나

로드맵은 **1단계 ERP Setup · 2단계 ERP 기반 리스크 조기 탐지 Setup** 이고, 지금은
그것을 완수하기 위한 **작업 환경을 조성하는 중**이다. 물음은 「부족한 점 목록」이
아니다 — 목록은 이미 있다(`2026-09-10-workflow-migration-design.md` 의 대장 18행과
빈 자리 넷).

> **묻는 것은 「환경 조성을 언제 멈춰도 되는가」다.** (사용자 발화)

멈출 자리가 없으면 환경 일감이 스스로 번식한다. 실제로 지금 **열린 이슈 20개가 전부
환경·워크플로 일감**이고 제품 일감은 하나도 없다(실측). 이 상태가 나쁘다는 뜻이
아니라, **어디까지가 「충분」인지를 아무도 적어 두지 않았다**는 뜻이다.

## 5. 접근 방식과 기각한 대안

설계도의 **대장 18행 + 열린 이슈 20개**에 한 행씩 묻는다:

> **이것이 없으면 사람이 매번 손으로 실어 날라야 하는가?** (사용자가 고른 판정 기준)

「예」면 **막는 것**, 「아니오」면 **멈춰도 되는 것**이다. 이 기준은 설계도의 진단 한
줄(*"규칙이 파일이 아니라 발화로 전달되고 있다"*)과 같은 축이므로, 앞서 나온 판단과
대조가 된다. (추정 — 기준이 같은 축이라는 것까지가 내 판단이다)

**기각한 대안**

| 기각 | 이유 |
| --- | --- |
| 「틀린 결과가 조용히 지나가는가」로 판정 | 사용자가 고르지 않았다. 이 축을 쓰면 린터·회귀 검사가 앞으로 오는데, 지금 아픈 것은 **규칙 운반**이다 |
| 둘의 합집합 | 최소 집합이 커져 중단선이 늦게 선다 — 중단선을 묻는 물음에 답이 되지 못한다 |
| 2단계 첫 일감을 가상으로 전개해 역산 | 가장 좋은 기준이지만 **가상 전개가 추정을 한 겹 더한다.** 사용자가 고르지 않았다 |
| 새 판정 축을 발명한다 | 설계도가 이미 실측 위에 서 있다. 축을 새로 만들면 기존 판단과 대조가 안 된다 |
| 열린 이슈 20개를 전부 재분류·재정렬 | #48 의 자리를 침범한다. 이 문서는 「무엇이 막는가」만 묻는다 |

## 6. 사실 근거 상태 — 무엇을 닫고 무엇을 남기나 (사용자 확인)

**이번에 재서 닫는 셋**

| 미검증 | 어떻게 닫나 | 왜 닫나 |
| --- | --- | --- |
| CI 실제 소요 시간 | Actions 실행 이력을 API 로 읽는다 | #55·#61 의 회수 크기가 여기 달려 있고, 설계도가 「25분은 미검증」이라 적어 두었다 |
| 검사가 지금 실제로 도는가 | 두 엔진으로 백엔드 검사를 돌린다 | 「환경이 서 있다」의 가장 기초적인 증거인데 오늘 재 본 적이 없다 |
| `mcp` 능력이 커넥터에 닿는가 | 능력 로스터를 먼저 보고, 필요하면 최소 시험 페이지를 하나 발행한다 | 설계도 §7 의 미검증. **범위 밖 산출물이 하나 생길 수 있음을 알고 고른 것이다** |

**미검증으로 남기는 둘**

| 미검증 | 왜 남기나 |
| --- | --- |
| 저장소 밖 설정의 현재 값 (#51 이 켜졌는지 등) | 403. §4 의 처분대로 **저자 확인 명령지**로 넘어간다 |
| 로드맵 1·2단계와 P1/P2 마일스톤의 대응 | 저장소 어디에도 적혀 있지 않다. **재는 것이 아니라 정하는 것**이고, 제품 진척은 범위 밖이다 |
| Projects 의 로컬 자격증명 범위 | 사용자가 고르지 않았다. 설계도 §5 의 측정 그대로 남는다 |
