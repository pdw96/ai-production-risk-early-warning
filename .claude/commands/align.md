# 정렬 게이트

대상 주제: $ARGUMENTS

목적: 사용자의 의도와 내 이해가 일치하는지를 **채점 가능한 형태로 드러내고**, 기준을
넘기 전에는 구현을 시작하지 않는다. 점수 자체가 목적이 아니라, 내 이해를 사용자가
"그거 틀렸다"고 짚을 수 있는 조각으로 분해하는 것이 목적이다.

## 절차

1. **먼저 조사한다.** 저장소·환경에서 확인할 수 있는 것은 사용자에게 묻기 전에 직접
   확인한다. 코드로 답이 나오는 걸 질문으로 소비하지 않는다. 이미 `docs/`에 관련
   핸드오프 문서가 있으면 읽는다.
2. **채점표를 낸다.** 아래 6개 항목마다 세 가지를 적는다.
   - 내가 이해한 내용 (한두 문장, 구체적으로. "적절히 처리"류 금지)
   - 점수 (0–3)
   - 근거 (사용자 발화 인용 / 실측 결과 / 내 추정 — 셋 중 하나를 명시)
3. **게이트를 판정한다** (아래 기준).
4. **미달이면 질문한다.** 가장 낮은 항목을 올릴 질문만 **최대 3개**. "더 알려주세요"
   같은 포괄 질문은 금지하고, 답이 곧 특정 항목의 점수가 되는 질문만 한다.
   답을 받으면 2번으로 돌아가 **재채점**하고 점수 변화를 보여준다.
5. **통과하면** 실행 프롬프트를 `docs/YYYY-MM-DD-<슬러그>.md`로 쓰고, 사용자 승인을
   받은 뒤 작업에 들어간다.

## 루브릭

| # | 항목 | 무엇을 보는가 |
|---|---|---|
| 1 | 문제 정의와 동기 | 무엇이 문제이고 왜 지금 하는가 |
| 2 | 완료 조건 | **관측 가능한** 형태로 "끝났다"를 판정할 수 있는가 |
| 3 | 범위 경계 | 포함되는 것과 **명시적으로 제외되는 것** |
| 4 | 제약과 함정 | 환경 제약, 비협상 조건, 이미 아는 함정 |
| 5 | 접근 방식 | 택한 방법 + **기각한 대안과 그 이유** |
| 6 | 사실 근거 상태 | 각 전제가 실측인지 추정인지 미검증인지 라벨링됨 |

### 점수 기준 (출처 기반 — 확신도가 아니라 출처로 매긴다)

- **3** — 사용자가 명시했거나, 내 요약을 사용자가 확인해 줬다
- **2** — 사용자가 말했으나 모호하거나 일부만 다뤘다
- **1** — 내 추정일 뿐, 사용자가 말한 적 없다
- **0** — 아예 다뤄지지 않았다

"내가 잘 이해한 것 같다"는 점수를 올리는 근거가 되지 않는다. 근거란에 사용자 발화를
인용할 수 없으면 그 항목은 2점 이상을 줄 수 없다.

## 게이트 기준

총점 18점 만점. 아래를 **모두** 만족해야 통과:

- 총점 **14점 이상**
- 항목 **2(완료 조건)와 3(범위 경계)이 각각 2점 이상**
- **0점 항목 없음**

2번과 3번을 따로 묶는 이유: 나머지가 아무리 높아도 이 둘이 비면 "열심히 만들었는데
원하던 게 아닌" 결과가 나온다. 총점으로 상쇄되지 않게 한다.

## 예외

- 사용자가 미달 상태에서 **그대로 진행하라고 하면 진행한다.** 단 채점표는 남기고,
  미달 항목을 "가정"으로 명시한 뒤 작업한다. 되묻지 않는다.
- 사용자가 점수를 정정하면 (예: "그건 3점 아니라 1점이야") 그 판정이 최종이다.
- 사소한 단발 작업(파일 읽기, 단순 질문, 한 줄 수정)에는 이 게이트를 적용하지 않는다.

## 통과 시 산출물 형식

`docs/`의 기존 핸드오프 문서와 같은 형식을 따른다:

- 맨 앞에 이 문서가 무엇이고 사실들이 언제 어떻게 확인됐는지
- **실측 / 추정 / 미검증**을 문서 전체에서 구분해 표기
- 알려진 함정은 재현 증거(로그, 명령 출력)와 함께
- 마지막에 통과 시점의 채점표를 그대로 첨부 — 무엇이 확인된 사실이고 무엇이 가정
  위에 서 있는지가 나중에 보이도록
